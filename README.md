# نظام إدارة المخزون — صفحة موردو المخزون

تطبيق ويب لإدارة أصناف موردي فرع واحد من المخزون: استيراد من إكسل، تعديل يدوي، تصدير، وطباعة مقسّمة حسب المورد.

## التقنيات

- **الخادم**: Node.js + Express + SQLite (`better-sqlite3`) + `exceljs` لقراءة/توليد ملفات إكسل.
- **الواجهة**: React + Vite + Tailwind CSS، بتصميم عربي (RTL) بالكامل.

## التشغيل محليًا

```bash
npm run install:all   # تثبيت حزم الخادم والواجهة
npm run dev            # تشغيل الخادم (المنفذ 4000) والواجهة (المنفذ 5173) معًا
```

افتح المتصفح على `http://localhost:5173`.

## آلية عمل الصفحة

- **الاستيراد**: رفع ملف إكسل يحل محل بيانات الفرع الحالية بالكامل (كل فرع يُرفع له ملفه الخاص بشكل منفصل، فلا حاجة لاختيار فرع عند الاستيراد). الأعمدة المتوقعة في الملف:
  - رمز المورد → **المورد**
  - اسم المورد → **الاسم**
  - اسم مجموعة المخزون → **البيان**
  - الموديل → **موديل**
  - الرصيد الحالي → **الرصيد**
  - السعر الحالي → **السعر**
- **التعديل**: إضافة/تعديل/حذف أي صنف مباشرة من الجدول.
- **الترتيب** (مطبّق في العرض والتصدير والطباعة): حسب المورد تصاعديًا، ثم داخل كل مورد حسب **البيان** تنازليًا، ثم حسب **الرصيد** تصاعديًا.
  > ملاحظة: طلب المستخدم كان الترتيب حسب "الصنف" — بما أن الحقول المستخرجة لا تحتوي عمودًا بهذا الاسم بالضبط، تم اعتماد عمود **البيان** (اسم مجموعة المخزون) باعتباره الأقرب لمعنى "الصنف". يمكن تغييره بسهولة في `server/src/sort.js` إذا كان المقصود عمودًا آخر.
- **التصدير**: ملف إكسل يحتوي جدولًا منفصلاً لكل مورد، يفصل بينها مسافة صغيرة، ليسهل قص الورقة عند الطباعة بحيث يكون كل مورد في ورقة مستقلة.
- **الطباعة**: نافذة تطلب اسم الفرع والفترة (من/إلى) قبل الطباعة، وتُستخدم هذه القيم في رأس الصفحة المطبوعة فقط (لا يوجد عمود تاريخ في البيانات نفسها).

## هيكل المشروع

```
server/   Express API + قاعدة بيانات SQLite (data.sqlite تُنشأ تلقائيًا)
client/   واجهة React
```
